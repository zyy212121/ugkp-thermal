THERMAL NUMERICAL CONTROLS: IMPLEMENTATION HANDOFF

Scope and authorization
Implemented CHT solid nonlinear/interface/linear, shared DO radiation, particle material radiation, and active coldwall1D controls in root FP64 and FP32 overlay paths. No README changes, commits, pushes, compilation, mathematical/operator/solver tests, or background-D intervention. Static source inspection only. Numerical conclusions are pending the parent's single unified D acceptance.

Current user instruction (supersedes initial compatibility proposal)
Numerical controls are read only from constant/scheme via common/FoamSolverScheme.H. Old numerical entries in solidRegionProperties, fvSolution, radiationProperties, and particleProperties are no longer fallbacks. Missing scheme fields use the typed defaults below. Model/material/boundary configuration remains in its original files. The user requested matching case migration; another owner is migrating candidate copies, not the original case-current.

Precedence and lifetime
Precedence, high to low: regions.<region>.<module>.<key>, <module>.<key>, then the selected backend typed effective default. The parent loader owns one read-only case snapshot. Each thermal owner resolves controls at construction and stores typed values; kernels do not read dictionaries. CHT linear normal/final dictionaries are built once, independently, from defaults plus scheme. There is no fvSolution numerical read in the candidate solver. Runtime changes to constant/scheme are not observed until restart.

SOLID NONLINEAR
Module: solid.nonlinear; region is the solid mesh name. Both primary and auxiliary regions can override separately.
Keys and defaults:
 nonlinearMaxIterations: label, 50.
 nonlinearRelativeTolerance: dimensionless scalar, FP64 1e-10; FP32 effective default 1e-5.
 energyRelativeTolerance: dimensionless scalar, FP64 1e-8; FP32 effective default 1e-4.
 energyAbsoluteTolerance: energy J, scalar, 1e-10.
 nonlinearAitken: bool, false.
 nonlinearInitialRelaxation: dimensionless scalar, 1.
 nonlinearMinimumRelaxation: dimensionless scalar, 0.05.
 nonlinearMaximumRelaxation: dimensionless scalar, 1.
The production caller supplies GpuSolidThermalControls{} rather than reading old solidRegionProperties numerical values. FP32's approved engineering defaults are applied before explicit scheme values; no later constructor clamp undoes an explicit scheme value. Direct callers can still construct the existing typed control API. Configured/effective FP32 logging is retained and describes the override order.
The CPU candidate loop and SolidThermalIterationGraph consume the same controls. The nonlinear tolerance controls cell temperature, surface temperature, and surface-flux changes. Energy acceptance remains abs + rel*max(abs(deltaH),abs(interface)+abs(external),1). Aitken uses the existing initial/min/max relaxation. Existing budget-exhaustion warning/retain-candidate semantics are unchanged. Aitken on/off and host/distributed versus resident graph are distinct coverage branches.

DO RADIATION
Module: radiation.do; region is the fluid/gas mesh name. Active only when the existing radiation model is enabled.
 maxSourceIterations: label, 300.
 sourceRelativeTolerance: FP64 1e-10; FP32 max(1e-10,32*float epsilon).
 phaseBalanceTolerance: FP64 1e-12; FP32 max(1e-12,max(32,8*nTheta*nPhi)*float epsilon).
 maxPhaseBalanceIterations: label, 200.
 radiationActiveEpsilonMin: dimensionless scalar/RadiationReal, 0.
 angleParallelThreads: label, 1.
 sourceRelaxation: dimensionless scalar/RadiationReal, 1.
 linearSolverTolerance: FP64 1e-12; FP32 max(1e-12,32*float epsilon).
 linearSolverRelTol: dimensionless scalar/RadiationReal, 0.
 linearSolverMaxIterations: label, 1000.
Existing default tolerance calculation remains min(1e-12,typed sourceRelativeTolerance*0.01) before resolution; with typed source default 1e-10 it equals 1e-12. Explicit scheme source tolerance does not implicitly rewrite a separately defaulted linear tolerance.
Production MieDo owner applies precision defaults once, then scheme overrides. RadiationControls.controlsAlreadyResolved is true on the owner-to-GPU path; DiscreteOrdinateRadiation and OrderedUpwindGraph do not reclamp those explicit values. Direct GPU API callers leave the flag false and retain their previous precision-floor behavior. The independent MieOpticalProperties direct API keeps its original default floor and is not a hidden production scheme consumer.
Actual consumers: active threshold in optics/import; phase iterations/tolerance in balancePhase; source iterations/tolerance in the conditional source graph; sourceRelaxation in relaxedDirection; linear settings in OrderedUpwindGraph, including published-residual measurement; angleParallelThreads in concurrency/frozen-angular-source selection.
nTheta/nPhi and Mie tables, radiation enable/schedule, boundary types/emissivity remain model inputs. conservationRelativeTolerance and maxPhaseScalingCorrection were dead fields: old reads are removed, no new consumer or rejection behavior is introduced. They are not migrated to scheme.
Coverage needs source/phase/directional-linear budget exits and converged exits, relaxation=1 versus !=1, and sequential versus parallel angular policies. Radiation-disabled fixtures do not cover these controls.

PARTICLE MATERIAL RADIATION
Module: radiation.material; region is the fluid/gas mesh name.
Typed struct: ugkp::gpu::ParticleRadiationSolveControls in common/gpu/ParticleRadiationControls.H.
 boundedMaximumIterations: int, 100.
 boundedTemperatureRelativeTolerance: FP64 1e-10; FP32 max(1e-10,8*float epsilon).
 boundedEnergyRelativeTolerance: FP64 1e-9; FP32 max(1e-9,32*float epsilon).

All scalar tolerances here are dimensionless. Material coupler construction resolves this struct once and passes it to the long-lived ParticleRadiationMaterial owner. materialRoots uses the bounded controls when response.enabled is false; caloric controls when response.enabled is true. The same boundary tolerance feeds raw conservativeMaterialBoundary and actual settleMaterialBoundary. Existing roundoff allowance, endpoint choice, representable-interval stop, conservation policy, and physical bounds are unchanged. The material constructor's default second argument preserves direct API defaults. No old file keys exist for these formerly hardcoded values.
Observation gap: production MaterialResult exports temperature/energy but currently not material-root iterations/residual. Direct solveCaloricParticleRadiation returns iterations/residual. Existing bounded root functions also return iterations/residual, but the material kernel does not export them. A manifest must not infer both branches from a single enabled radiation run or from SCHEME_VALUE parsing alone. No synchronization/readback was added solely for diagnostics in this patch.

COLDWALL1D
Module: coldWall1D; region is fluid/gas mesh name.
 solidificationIterations: label/int, 4.
CHT configureParticleStuckModel resolves the default plus scheme and sends it through the existing nonlinearIterations parameter. The active 8-node kernel consumes that member; full-solid first-iteration early exit remains. No new convergence gate/tolerance/relaxation was added. CHMT owner is integrating the same section/key through its shared reader.
The main thermal backend uses GPU_PAIRED_PARTICLE_HEAT and analytic ParticleCaloric::temperature; the old 40-bisection fallback is not a new control. PCR stride count, node/ring counts, structural mass allocation loops and 2D legacy are unchanged. Coldwall1D must actually be active and cross the nonlinear regime to observe a changed iteration budget; a fully solid one-step analytic exit is not budget-trend coverage.
