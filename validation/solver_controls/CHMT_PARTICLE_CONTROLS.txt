CONSUMPTION
CouplingInput reads controls before validateRuntimeState and constructs model.
material controls are passed to CpuMaterialDriver.advanceCandidate:
nonlinear loop, energy stopping, sparse solver maxIter/tolerance,
material substep and reaction schedules consume their corresponding fields.
PhysicsConfig.numerics -> material thermo inversion, least-squares reconstruction,
InterfaceComposition and InterfaceMath iterations and Geometry/SweepControls.
GPU material backends copy the PhysicsConfig including numerical settings.
ParticleCouplingStorage passes packing to phase configuration and calls
setParticleNumericalControls after owner creation; thermal resident stores
packingProjectionIterations and particleFiniteContactMaximumIterations.
GpuParticleThermalConsumerDevice passes the latter to the finite-contact solver.
Contact nonlinearIterations enters the pre-existing shared coldWall configuration.
Both base and precision/fp32 paths audited.
CHMT_SOLVER_CONTROLS reports actual input structures at backend/driver creation;
this plus source wiring is producer evidence, not proof an inactive branch ran.
No new evaluations, synchronizations, rejection gates or timestep logging.

LEGACY / RESTART
Old chmtProperties minDt/maxDt/cfl/spatialOrder/materialReconstruction,
tolerances, cpuMaterial, multirate gasMaxDt/materialMaxSubstep,
particle packingIterations/contact nonlinearIterations no longer read as controls.
Physical calorics/material laws, particle min/max temperature, model switches,
mesh identity, coupling schedule, restart/output paths remain at original locations.
maxCouplingIterations/maxRetries were parsed historical fields without active
consumers; do not advertise them as adjustable working algorithms.
Checkpoint decode retains historical layout. Only comparison copies normalize
packingIterations/contact nonlinearIterations, so changing numerical budgets does
not change physical identity. All other physical comparison fields remain intact.
Expected startup ModelConfig is retained; saved HostState is restored.

PLANNED ACCEPTANCE (NOT RUN HERE)
Shared-boundary chmt fixture is shortest gas/material default example:
minDeltaT1e-12, maxDeltaT1e-5, maxCo.4; coupling .0005; end .001.
It has no particles/reactions/radiation, so cannot cover those branches.
Suggested non-exhausting override: conduction linearMaxIterations2100,
nonlinearMaxIterations55, particle packingIterations22/contact iterations5
ONLY on a predeclared active particle fixture; finiteContact104 only where contact
solver is active. Require startup values plus actual completion/finite fields and
existing convergence/conservation criteria. No forced failure budget tests.
Restart: process A writes outputDirectory/checkpoint-N; process B sets
restartDirectory to it, distinct outputDirectory and later endTime, with controls B.
Use a particle-enabled case to verify the changed numerical identity controls.
Final acceptance owner must enumerate exact cases/processes and freeze before run.

Gas discretization: gasNumerics module (legacy fvSchemes-shaped keys) now passes
through shared readGasNumericsDictionary(time,gasRegion); CHMT no longer reads
gas numerical schemes from mesh.schemes(). Physical model choices stay separate.
