# 双库公共算子统一与低负载评估

这是早期 R2 阶段的历史记录，保留当时数据和限制；不能作为后续算子合并或 auto 恢复的验收结果。后续验证见 [六项合并](development/operator-unification-20261004/README.md) 和 [本次收尾](development/auto-cleanup-20261004/README.md)。

## 工程结果

本轮收口了公共主机流程、宏与类型契约、已登记字段生命周期、跨库镜像归属四类维护问题。三个应用的公共算子通过同一实现维护；有限接触由 FSH/CHT 共用，CHT 独有固体和辐射功能保留自身入口。后续公共算子优化修改其共同所有者，不需要分别移植三套实现。

| 范围 | 共同所有者与约束 |
| --- | --- |
| 气相 Euler/RK、边界和图流程 | GpuGasAdvance.cuh / GpuGasHostPolicy.cuh；保留时间、权重精度与壁能账本能力 |
| 粒子追踪、packing 与目录 | GpuParticleTransport.cuh / GpuMobilePackingHost.cuh / GpuParticleDirectoryHost.cuh；gas 的静态目录生命周期有明确边界 |
| 矩规约、搬运与恢复 | GpuParticleMoments.cuh / GpuSegmentedMomentWorkers.cuh / GpuMomentPipeline.cuh |
| Poisson 粒子选择与池 | GpuCollisionPoolParticle.cuh / GpuPoolSelection.cuh；应用和层级共用访问顺序 |
| 压力公共流程 | GpuPressurePipeline.cuh / GpuPressureConstrainedPhysics.cuh；精度与原舍入路径保留适配层 |
| 有限接触 | common/operators/FiniteContactRelaxation.inl；if/else 控制归调用者 |
| 字段生命周期 | ParticleFieldManifest.json；声明、分配、释放、copy/swap 与 thermal schema7 wire 检查 |
| 类型与调度接口 | GpuOperatorContract.cuh / GpuLaunchOptions.cuh / GpuPressureFlatLayout.cuh |
| 双库维护 | managed_mirrors.json：231 项登记镜像，明确上游、白名单同步和构建漂移检查 |

公共代码的权威来源是 `ugkp-thermal/common`；gas 应用入口的权威来源是 `gpu-riemann-gkp-main/applications/gasUGKP`。两库保留独立构建所需副本，镜像工具负责机械同步。公共实现归属测试从实际入口解析包含关系，确认所测八项核心函数在各应用均指向唯一公共定义。

本轮最后一项公共优化将接受粒子后的 RNG 写回、热字段读取顺序统一到共享函数，移除 `GPU_POOL_S1_LATE_THETA_AND_RNG` 应用/层级开关，并合并重复的分段粒子包装函数。它适用于合法的 Poisson 粒子选择流程，不依赖具体案例、无接触壁面特例或经验负载常数。拒绝粒子的 RNG 更新、非 Poisson 分支、每线程累加顺序和接触字段语义得到保留。

当前最终候选共 288 次运行：48 次预热、240 次测量。每个应用、每个负载共十对，B1 自动、B2=B3=64、FP64，200 步/20 个采样点；采用均衡的 Williams 顺序。原始物理输入和 mesh 在同负载比较中保持一致。最初五对完整保留，用户明确要求增加至十对后，再预先冻结并执行补充五对；没有按通过与否追加样本。两个五对时间块的中位数另行报告，避免隐藏时间漂移。

## 低档位瓶颈与停止优化的依据

当前 FSH k2 的 200 个实测 L2 样本中，松弛约占整步 42.01%，前后压力与追踪加上松弛合计的逐步占比中位数为 72.96%；这些主体为两层级共用。L2 并不会把整步所有粒子工作一起缩短。当前输入的 cell 占用 p99 约为 4500，远低于约 1.3 万的硬件推导 tile 量级；最大占用 14500–22500 又明确说明存在重载，不能把 k2 解释为没有触发重载。

十对逐阶段差的中位数显示，L2 的后矩约省 98.0 微秒，同时目录前/后分别增加 45.5/14.8 微秒，pool 增加 25.1 微秒。它们支持“有限长尾收益与额外组织成本相抵”的判断；各阶段中位数不能相加冒充总差，整步独立计算的配对差中位数为 3.120 微秒。

对同一实测二进制的 199 个周期步追踪中，GPU 核执行时间占该周期区间约 98.82%（L1）/98.87%（L2）。执行已主要受 GPU 核工作限制，不能把主机提交视为主要空转来源。L2 的四次额外 4 字节清零各自仅约 0.32 微秒 GPU 时间、3.6–4.0 微秒主机 API 中位时长；主机与 GPU 时间存在重叠，这些数字不是可直接相加的整步收益。

据此确认当前低档位分段规约的实用收益瓶颈，并接受接近 1 的 FSH 结果。没有证明所有未来公共优化都无效，也没有测得硬件峰值带宽上限。继续为约 0.012% 的比值缺口引入新队列协议，当前缺少足够收益依据，因此停止该方向。

瓶颈确认限定为当前 k1/k2 下分段 L2 相对 L1 的收益空间；它不是 GPU 已达到理论带宽或所有算法已全局最优的证明。分析使用正式计时样本及相同实测二进制的 Nsight Systems 追踪，追踪结果不混入效率测量。主机 API 与 GPU 执行存在重叠，不相加冒充可移除的整步开销。

队列清零融合仅建立了独立试验草稿。收到“不强行优化”的要求后已隔离，未通过绿色/原生/性能验证，未合并到本交付。源码维护收口与追求微小加速分别评估，没有用未经验证的额外复杂性替代已确认的公共实现。

## 正确性与来源核验

- 继承已验证的主机流程、字段、任务目录与物理算子证据；新增改动另做实际原生对照。
- gas64、FSH64、CHT64、CHT32 共 616 组修改前后状态比较：选中粒子、RNG 与接触状态哈希一致，矩结果通过独立 CPU 计算；覆盖完整/分段目录、混合注入与多种规约块大小。
- 有限接触集成在两个层级均运行 100 步，23 个最终字段与轮次基线逐字节一致；该结果不推广为所有随机场景必须位一致。
- 最后公共访问策略改动仅改变 9 个 Poisson 池核的 SASS：gas 6、FSH 1、CHT 两种精度各 1；其余核指令保持一致。两库独立构建的 gas 全部 135 个核一致。
- DeviceState 声明及初始化器保持一致；源码、真实 ELF、原始 timing.csv、输入清单和构建记录均有 SHA256 绑定。
- 编译器/控制进程中断的尝试保留在原始日志；未以降低优化等级或改变浮点选项通过验证。

## 保留的数值边界与已知问题

阻力的小 Re、clamp/regularization 与压力发布舍入保留原有兼容行为，公共公式和适配边界已集中；本轮没有声称这些历史差异在理论上必需，也未把代数相近当作浮点等价证明。已登记字段闭包通过不等于穷尽资源耗尽回滚和所有损坏 restart 输入。

既有约 **1.09% 换热缺口仍未修复，严格能量闭合仍为 FAIL**。本轮没有修改对应热交换/relaxation 核；未将缺口未恶化或其它正确性检查写成能量闭合通过。

规约 B3 仍为 64。任务 tile 使用当前所选规约路径的实际驻留能力：`B3 × max(1, ceil(N / (B3 × SM × residentBlocksPerSM)))`。S2/L2 的历史 `lightBlocksPerSm` 字段可能承载 heavy worker 的驻留值；它不是固定的实际 L1 核占用率。约一万是该硬件和粒子规模下的量级，不是新增经验参数。CUDA 启动网格表示线程块数，与 blockMesh 物理网格划分无关。
