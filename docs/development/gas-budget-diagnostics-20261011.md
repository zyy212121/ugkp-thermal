# Opt-in accepted pure-gas budgets

Scope: fixed pure `mixtureFrozen`/`mixtureChemistry`, no particles or gravity. This is diagnostic instrumentation, not a state repair or an acceptance-tolerance change. CHMT keeps its existing exchange ledger. Opted-in legacy single-gas graph-capture and combined gas/particle advance are rejected at their entry guards. Mesh upload is rejected after the segment captures its accepted initial inventory. Disabled legacy graph capture remains untouched.

Set `UGKP_GAS_BUDGET_OUTPUT` to an absolute path that does not exist. The resident allocates double pending external-transport channels `[mass, formation-inclusive total energy, species...]`, an RK initial copy and actual chemistry-species increments. Disabled diagnostics add no independent audit-buffer allocation, transfer, application-kernel launch or output. Existing state storage/copies grow and existing kernels retain runtime audit checks; this is not a zero-cost claim. Shared operators without the optional capability compile without audit work.

Recording points:
- `applyGasFluxDivergenceByCellKernel`: existing face traversals, after the pipeline's final positivity limiting and periodic antisymmetry. Only physical external faces contribute to external budgets; inward positive. Failed-attempt scratch is transaction-owned and cannot become accepted output.
- `saveGasConservativeStateKernel` / `blendGasConservativeStateKernel`: identical passed RK weights, converted to double. Do not reuse wall-only `ledgerDt`: the pure-gas no-wall-energy policy returns zero for its RK hooks.
- `advanceGasChemistryCell`: after candidate validation, record `(published species density - original density) * actual stage volume`. The species conversion is actual publication, not an ideal pre-conversion reactor result. No extra chemistry energy source is invented.
- `SharedGasTrialPolicy`: pending arrays participate in both trial and requested-interval snapshots. A failed trial restores its pending arrays; a failed requested interval restores the prior accepted state and emits no accepted row. Trial commit alone never publishes. Requested-interval commit reads and reduces final pending channels and accepted inventories once.

Output is newline-delimited schema 1 JSON. A NEW_SEGMENT records accepted initial time/inventory, ordered species/elements, immutable model hashes and element mol/kg matrix. An ACCEPTED_INTERVAL records its sequence, interval start/accepted endpoint, current inventory, cumulative boundary transport and chemistry species, plus independent mass/physical-energy/species-update and elemental residuals. Elemental conservation does not subtract actual chemical elemental drift; that drift is reported separately. Boundary mechanical work, if prescribed, is already included in total-energy flux; no separate body-work source is assumed. Fixed geometry has zero GCL contribution. Undefined element bases stay explicitly unavailable.

Every new process, including restart, starts an explicitly unverified new segment. It never silently resets counters while claiming continuity. The PR13 reader can reconcile a segment chain only when prior accepted endpoint time, model identity and inventories match the next segment's accepted initial state. An isolated restart segment cannot establish cumulative history from time zero.

Enabled diagnostics add persistent arrays and both rollback copies. They currently read arrays to the host and perform long-double reductions once per requested interval. Inventories retain long-double precision through residual subtraction and decimal serialization; the reader likewise preserves serialized precision before computing balances. Records include extra device bytes, transferred bytes, zero explicit additional application-kernel launches and measured host inventory/reduction time. This partial timing excludes allocation, reset, snapshot, fused-kernel and file-I/O costs and is not an isolated GPU-throughput claim. Native on/off overhead measurement remains required before wider use.

Verification order: host-shim actual operator RK/limited-flux tests; actual transaction policy accept/reject/interval rollback and disabled-resource tests; real chemistry publication/zero-time/failure tests; CUDA native backend compilation/link; then native GPU small controlled cases when hardware exists. Do not substitute these checks for complete application physical acceptance.


## Bounded cost evidence (CUDA 13.1, sm_89, Ns=2 build)

A native sizeof probe using the production DeviceState definition and the same definition with only the new fields removed reports 4368 -> 4408 bytes, alignment 8. The audit view is 32 bytes and host-owner pointer is 8 bytes. Thus even when disabled, each existing host/device state allocation and full-state copy grows by 40 bytes. There is no additional allocation/copy *operation*. The enabled-only host ledger object is 232 bytes on this ABI, plus its vectors, strings, file buffers and temporary read/reduction vectors.

For N cells and S species, pending live arrays occupy B = 8 N (3 S + 4) bytes. Trial and requested-interval snapshots each add B, giving 3B = 24 N (3 S + 4) bytes of audit arrays; `audit_device_bytes` reports these arrays, separately from the 40-byte state-layout increase. Interval start performs three cudaMemset calls over a total B bytes. Each additional snapshot or restoration transfers B bytes device-to-device within the existing per-field copy mechanism. Their runtime/device cost is not measured here.

Accepted-interval diagnostics read B bytes device-to-host: accepted inventory, boundary transport and chemical species. Initial segment capture adds 8 N (S + 3) bytes for volume and initial inventory. One accepted interval performs 3 S + 4 cell-array host reductions, plus two elemental matrix reductions (each E sums over S species). Initial capture adds S + 2 inventory reductions. There is one explicit device-view upload at configuration. Output is one header plus one JSON line per accepted interval, with size dependent on values, names and hashes. A two-cell/two-species host-shim receipt measured 605 header bytes and 896 accepted-record bytes, including newlines; this is an example, not a fixed output-size bound.

Disabled runtime checks remain in production kernels: external transport tests occur in the mass/energy incident-face loop and each species incident-face loop; audit helpers guard their writes; save/blend guard once per active cell; chemistry guards at validated species publication. The optimizer may combine or hoist checks, but no zero-instruction claim is made. The added fields also participate in existing state copies. Generic states without the optional capability use compile-time selection, which does not remove checks from the actual pure-gas DeviceState.

The compiled reviewed backend reports registers per thread: divergence 43, conservative save 20, conservative blend 22, chemistry 255 with a 1744-byte stack. These are absolute compiled resource counts, not a measured on/off delta. The runtime on/off states share these compiled kernels. `audit_extra_kernel_launches=0` means no explicit additional application-kernel launches; CUDA memset implementation work has not been profiled. GPU register occupancy, fused-check/recording time, resets, snapshots, file output and complete on/off overhead still require measurement on hardware. Host timing in receipts covers inventory reads/reductions only.
