# GPU源项／参考均值／面计算：相对2f4a66f是否加速

**有加速。** 相同初场和配置的20步原生GPU诊断中，源项／参考均值／面计算合计耗时为旧版的 **0.771788倍**，下降 **22.82%**，对应这部分约 **1.296倍**速度。336个墙面分别统计，全部墙面的该部分平均耗时都下降。

源项积分／参考均值下降24.87%，面计算反而增加55.59%，但后者占比较小，合计仍然更快。保守矩拟合及其准备增加82.94%，新增约17.643ms/墙面调用，超过源项／均值／面计算节省的约8.888ms/墙面调用，使整个融合重构函数仍慢14.54%。本轮没有修改生产算法，属于分项诊断。

## 纠正前一轮统计范围

CPU数学报告的`sourceFaceSeconds`计时包含：两段`baseAverage`、两段`sourceTeam`、三张面的inviscid/diffusive flux以及少量输出累计。旧源项积分原生用4个子区间，新coherent路线用1个；CPU报告记录合计耗时0.53471倍，即下降46.53%。

GPU这部分在 `common/gasTransport/GasConservativeWall.H::reconstructConservativeWall` 内，和 `fitTeam` 融合进同一个 `reconstructConservativeWallPool` 核函数。前一轮Nsight Systems中该核函数235.722→269.559ms/步，包含拟合与源项／均值／面计算的全部变化。它不能证明其中每个部分都变慢。

前一轮“其他GPU核函数基本不变”的分类没有覆盖这里的源项／均值／面计算，不能拿它否定CPU观察到的加速。独立的`computeGasInternalFaceFluxKernel`、`applySstFluxAndSourceKernel`也不是CPU上述计时段的对应物。

在两个隔离源码副本中，只修改`GasConservativeWall.H`，添加相同的三段设备`%globaltimer`计时、warp边界同步和段末printf：

## 与CPU结果的关系与边界

现在可以确认GPU这部分也加速了，因此不能把整个融合重构核函数增加14.35%的耗时解释为源项计算也变慢。GPU上源项／均值／面计算节省了时间，但拟合及准备增加得更多，BVP又有更大的增量。

CPU的46.53%来自4,000个固定混合组分时序输入的串行回放；这里的22.82%来自纯Air初场的20步应用演化。CPU与GPU的分段边界也有细微差别，例如GPU实际保存三张面的单边trace。旧、新GPU共享初场和配置，但各自数学版本演化后的墙面输入轨迹未强制冻结相同。**所以不能用46.53%与22.82%的差直接量化CPU和GPU对同一冻结算子的效率差异。** 本轮结论严格限于当前20步GPU对照。

两端均完成20步，336/336墙面采集完整，计时分段之和等于总段。各自终态rho、rhoE、p、T、U、rhoU、k、omega、rhoY_Air、rhoY_CO2与各自未插桩正式二进制的20步结果逐点完全相同（十个字段最大差均为0）。这验证了本次计时没有改变这两条20步轨迹；不代表旧、新数值版本相互完全相同。

生产工作区的数值源码、正式运行二进制均未修改，诊断副本和构建位于`work/pr22-native-cuda-20261021/profile-source-face-20steps/`。全部计算已结束，无后台solver或profiler残留。PR保持草稿，不合并。
