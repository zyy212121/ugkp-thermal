# 遗留路径、保留机制及原因

源码基准：`edc536ef5e662b7d1a571c0f1baa83fbe6ed7657`。这是发布前清单；发布后的核验结果另记。以下未完成项不是被默认为允许的门禁，也不表示本 PR 可以据此自动合并。

## 尚未完全接入统一 error/warning 的路径

| 位置 | 当前实际行为 | 为什么未在本轮完成 |
|---|---|---|
| `applications/CHT/thermal/GpuSolidThermalCoupler.C::solveTemporarySolidCandidate` | 固体非线性迭代到上限后采用最后状态，未增加统一精度 warning；非有限线性残差抛 `GpuSolidThermalSolveError` | 此独立 CPU 固体求解器未实施统一诊断迁移。当前生产入口未找到将该异常转换为原生 FatalError 的 catch，仍是明确遗留 |
| 同文件三域界面固定点循环 | 同一交换区间内重复解两侧导热方程，按界面温度／能量残差迭代，到上限采用最后结果 | 按数学耦合求解保留迭代；上限未收敛 warning 尚未接入，不应把保留数学方法等同于诊断已完成 |
| `applications/CHT/thermal/MieDoRadiationSolver.C` 及相平衡调用 | DO 线性／散射源迭代到预算后接受最后结果；部分相平衡指标由调用方丢弃 | 辐射模块未全部迁移，需单独接入残差 warning 和物理错误；不是时间步重试 |
| `common/gasWall/WallGeometryBuilder.H` | 几何构造失败返回 WallStatus，调用方再处理 | 底层形状、三角化、支撑表示限制与数值条件尚未逐项拆分，详细几何量记录不完整 |
| `applications/CHMT/mesh/EmptyExtrusion.H` | 保留 Empty 网格拓扑、层数、运动表示等限制 | 缺少受支持表示与有限几何误差必须逐项区分；当前主要经上层几何错误字符串报告，没有逐处结构化量值 |
| `applications/CHMT/film/CpuFilmDriver.C` 部分 `numericReject` 分支 | 单次失败返回错误字符串／来源，再由材料入口终止 | 名字保留不代表重试；但每个底层分支的变量、实体索引还未全部转为详细记录 |
| `common` 中部分配置选择／物性辅助函数 | 例如 `gasHasDirectConductivity` 的 NaN 比较仍可能视作“未配置” | 未改变这些配置约定；非法配置和既有 sentinel 的逐项界定仍未完成，不能声称任何 NaN 都已有精确现场 |
| `applications/CHT/diluteUgkwpFoam.C` 非热耦合 `runTime.write()` | 未检查返回的 bool；热耦合持久化另有检查 | 输出 I/O 错误不是数值候选机制；本轮未改该独立写场路径 |
| 化学稠密线性求解失败 | 现报告线性系统的物理无效及原状态码，不再误称所有失败都是除零 | 仍未在消元源头逐一记录零主元与非有限矩阵元素的具体位置；不会继续计算，但现场细度有限 |

`SingleGasContract::validateSingleGasInventory`、`GasGeometryPolicy` 的部分完整状态辅助函数、`ResolvedNormalThermal` 的部分恢复函数仍保留定义；当前生产调用搜索未找到其调用。不能仅以“未找到调用”断言外部或其他构建永远不可达。这些辅助检查尚未逐项接入。

## 明确保留的计算机制

| 机制 | 保留理由 |
|---|---|
| 原有 HLLC／Roe 到 HLLE／Rusanov 的直接通量回退 | 用户允许的成熟直接回退；不做候选缩量后再试 |
| 梯度、原 limiter、正性限制及密度／能量下限 | 原数值算法的定义；没有用新候选搜索替代它 |
| SDIRK、RK、Strang 阶段 | 数学积分阶段，不是全步与半步误差对比重算 |
| Newton、线性求解、SST seed 固定点、标量求根及几何求积 | 求解既定数学问题；失败后改物理步长、换备用结果的路径已经分离删除 |
| 材料和气相物理子步、计算前 CFL／供体限制 | 每个成功子步推进实际时间，不是失败后缩步重放 |
| CHT 导热、三域耦合、辐射固定点迭代 | 数学方程的迭代解；其诊断缺口仍列在上表 |
| 粒子穿面上限与失活行为 | 用户明确排除粒子改造；未以此证明所有混合文件都已核查完毕 |

## 仍出现“恢复／重试”但不是物理重算的路径

- `SharedGasAdapter.cuh`、`SharedGasDeviceStorage.cuh`、`ResourceTransaction.H`：资源替换失败时恢复旧指针或使所有者失效，避免悬空设备地址；不重放一个物理区间。
- `GpuWallEnergy64.cu`：后续 API 调用重新发布待释放的 ledger 指针，属于资源生命周期。
- `GpuSolidThermalCoupler.C` 的异常清理：取消尚未提交的交换元数据后重新抛出异常，不重新执行求解。
- IPC 与 checkpoint 的短读、短写、EINTR 循环：继续完成同一次 I/O。诊断计数器 CAS 循环属于并发写入协调。
- `tool/CHT/bartzSolidReplay`：用户主动运行的离线回放工具，其目的就是重放记录；不是生产失败后的自动回退。
- 旧 checkpoint／wire 控制槽和已失去选择作用的模板布尔参数：为格式或调用兼容保留，不再选择备用算法。不能仅凭名字判断是否仍有重试。

## 审查边界

已经对全部生产目录建立路径清单并进行控制流标识扫描，关键执行链另作语义核查。机械扫描不等于每一行、每个模板实例和每个动态配置均已证明。发布后的审查必须更新到远端确切提交，并汇报仍发现的任何失败驱动候选、缩步、回退、重算或降级；本报告不提供无证据的“除此之外绝对没有”结论。
