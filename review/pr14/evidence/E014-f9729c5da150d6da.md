## Lifecycle decisions and actual implementation

### CHMT

- First initialization is detected by the actual allocated device-view owner, including identity/hash zero. It retains original allocation, initialization, table/geometry/state upload and final view publication order.
- Retain-resident configuration uses actual owned `rho` cell extent, resident `gasPhiRho` face extent, and cell-addressing extent. It does not consult species/thermo/mechanism identities as admission criteria. The compiled species-major stride remains `Ns`; no cell/species remap or padding was invented.
- A true layout replacement uses the supplied complete HostState and actual mesh arrays as the new inventory/layout source. Same-layout stale HostState sentinels never overwrite live cell, primitive, species, RK, SST, status or audit state. Explicit `uploadState` remains the existing same-layout import operation and retains its original integral-to-density arithmetic and trial-status clearing.
- Geometry-only upload changes geometry owners and publishes rebound addresses; it does not invent gas inventory or change the actual resident transport extent. A later complete configuration detects face-layout changes using the resident flux owner, not the already-grown geometry owner. A dedicated red/green case catches that distinction.
- The existing storage class itself is used as a temporary owner for replacement tables/layout, with constant-size pointer swaps and fault-owner rebinding. No normal full-state snapshot, D2H, D2D, synchronization or cell traversal was added. The old internal-face scan and redundant wall-list assignment are skipped when geometry is unchanged. New arrays alone receive the existing initial zero operations.
- Publication occurs after actual allocation/upload preparation. Failed preparation restores retained owners; failed view publication attempts the existing-view restoration. A second actual copy failure retains potentially exposed rejected allocations until teardown and marks the resident unusable. This is an actual device-publication failure path, not a metadata/numerical refusal. Optional first-enable SST/species failures do not corrupt or leak existing disabled owners.
- `deviceView()` remains stable across replacement. Every owner swaps its fault pointer back to its live owner. The actual Backend create, geometry-finish and restore call sites now rebind gasSpecies, gasBoundaryLayer, gasGeometry, deviceState and extents together. Existing caller publication is reused, avoiding duplicate view upload after geometry rebinding. There is no public hot Backend model-reconfiguration entry point in this tree; direct storage tests do not invent one.

### Native gasUGKP

- Reuse the existing `exchangePending` route. Presence of actual species `rho` storage, rather than old mode, chooses replacement. All seventeen dynamic pointers, including the previously omitted chemistry audit, retain addresses/bytes. Only actual supplied tables are allocated/uploaded on model reconfiguration.
- Existing explicit species and boundary upload operations still replace only their targeted arrays. Actual free errors are now returned, and retained failed pointers use the existing rejected species owner/poison lifecycle. Budget sequencing and actual file-open/error semantics remain in their existing owner.
- Native wall configuration is an explicit supplied wall-record import. Its current wall inputs/maps/exchange records are replaced as before; already-paid thirteen-array SST audit inventory is retained, including through audit disable and zero-wall disable. Actual missing consumed pointers, selected model absence, scratch/query/alloc/copy errors remain errors. Declared species count, compact-index range, geometry-index and nonfinite-flux admission checks were removed; tests do not execute invalid backing/index access.
- Shared SST reconfiguration retains live k/omega, conservative, initial and nut fields. First and legacy initialization still run the original seven field uploads, scalar-block upload, original initializer and synchronization.
- `sstJayatillekeP` and `sstThermalYPlus` are device-produced. Repeated scalar publication stops before these two trailing fields instead of overwriting them with host values. Existing host `sstWallKappa/E` fields survive the host scrub as last-completed configuration metadata. Same values require no kernel/sync. Changed values run exactly one thread of the existing initializer's original constant formulas with inventory initialization disabled, then the existing checked synchronization. Actual copy/launch/sync failures restore only the three host configuration markers needed to retry, not physical inventory.
- Dependency audit: `gasPrClamped` and `turbulentPrandtl` are assigned in DeviceState defaults, Create, and host scrub only; no runtime device update of those parameters exists. The original constant formulas consume the device values. P depends on Pr/Prt; thermal y+ additionally depends on kappa/E. See `dependencies.json` for exact source assignment lines.

## Actual capture and consumer audit

`common/GpuGasAdvance.cuh` graph capture contains kernels whose pointers are `deviceState`-indirect, including the RK save kernel. It does not capture a direct-array memcpy for RK storage. The capture nevertheless embeds host-selected model/RK/SST/periodic branches, launch grids, dt and refinement parameters. Native mixture advancement does not enter this legacy pure-gas graph path, but an older graph can exist across mode changes.

Accepted model/SST/wall configuration invalidates the existing graph-dt key and snapshot validity/prepared flag. Next applicable advance runs the existing destroy/capture/instantiate path exactly once. Pointer-only species/boundary imports invalidate existing snapshots/preparation without unnecessary recapture. The real graph host protocol test executes the actual common body with only CUDA launch syntax adapted, verifies unchanged reuse, pointer-only reuse, configuration rebuild, and eight injected actual CUDA lifecycle error classes followed by retry. Node introspection/time-parameter CUDA errors remain unchanged; those additional individual errors were not newly injected.

CHMT wall same-geometry output/input/exchange bytes are retained, then a real `evaluateGasBoundaryLayerSlot` consumes the newly uploaded thermo table and binds its fresh pointer. Preservation of a previously computed output does not assert that output is valid for a later time or model. Final stage readiness, current producer scheduling and dependent face refresh remain B7 work.

B5/B6 do not establish current-stage producer scheduling or refresh all dependent face output for stale records. B7 must close that real production chain, including HostState terminal material sampling.
4. Existing topology/shape checks outside the edited lifecycle entry points remain for final audit. No claim that the complete configure chain is now unrestricted. Existing native selected SST operator/boundary-mode checks were not expanded here.
5. No physical remapping is available from geometry-only upload; it supplies no new gas inventory. Supplied inconsistent counts/indices/SoA may still cause actual out-of-bounds access. No new capacity/index admission gate or padded state was added, and invalid backing cases are not executed as passing tests.

Simultaneous secondary CUDA free failures while discarding a partially prepared native wall candidate are not exhaustively injected. Generic CHMT Buffer still has its established pointer-clearing-on-free-error behavior; B6 reports the real error and does not claim recovery from every CUDA asynchronous failure.
