# Resident/frontend v2: source review and actual compilation only

The user changed validation scope after v1. This delta adds no CPU runtime probes or simulation tests and runs no application/host-shim numerical code. Earlier v1 evidence is retained unchanged and is not rerun. Actual GPU acceptance belongs to the user.

## Scope and preserved semantics

Nine physical production files are changed: CHT and FSH `readGpuGasConfiguration.H`, `createFields.H`, `diluteUgkwpFoam.C`, `gpu/GpuDragModel.H`, plus the actual shared owner `common/gpu/GpuBoundarySchedule.H`. CHT/FSH/gasUGKP schedule headers are tracked symlinks; they remain symlinks and all three consume the same changed owner. The gasUGKP gas configuration frontend already lacked the classified numerical/version preflight and was left untouched.

`records.json` provides stable review IDs RES-FE-001 through RES-FE-008, exact affected file/function scopes, removed admission work, preserved behavior, and GPU acceptance requests. Changes remove schema, numerical coefficient/floor/physical parameter, precision, redundant schedule/output and obsolete-control preflight only. Existing dictionary reads/defaults, mandatory model selection, FP64 expressions and assignment order remain. Unknown unimplemented thermo/scheme/turbulence/rough-wall models, missing selected geometry/files/fields, genuine ledger prefix absence and operation failures remain distinct.

Specific consequences to expose rather than hide:

- The actual thermo conversions remain RR/molWeight, Cv=Cp-R, gamma=Cp/Cv; removed checks do not replace an IEEE result or actual floating-point exception with a default.
- Existing first-face scheduled-inlet temperature is preserved. Newly admitted nonuniform inputs use that same representative choice, with no added average, clamp, scan or warning.
- Legacy partial-offload, random-bridge and representative-merge flags selected no available implementation in these mandatory resident paths. Their dead refusal reads/blocks are removed; no legacy feature is newly implemented or activated.
- FSH host heat output fields are already constructed under the host heat-enabled branch. Removing duplicate resident flag/name certificates does not remove actual output-field ownership. Ledger extents still must contain consumed face prefixes. The wall flux remains actual energy/(area*accumulationTime), including user-accepted unusual numerical outcomes.
- CHT exact writeInterval=-1 thermal-coupling sentinel remains unchanged. The extra blanket nonpositive precheck is removed; real OpenFOAM Time still owns its actual scheduling checks/division/modulo/conversion semantics.

## Compilation extent

`compile-frontends.sh` compiles actual CHT/FSH `diluteUgkwpFoam.C` translation units to objects, with UGKWP_USE_CUDA, WM_DP, actual relocated Foundation OpenFOAM10 headers, no mocked owner/dependency, and no source rewriting. Commands and logs are retained. No final application link, CUDA translation-unit compile, GPU launch, sanitizer or runtime numerical check is represented by this evidence.

The first actual builds both succeeded. A final CHT-only refresh is required after the final writeInterval deletion; the initial successful CHT evidence is preserved with `initial-` filenames rather than overwritten. Final status and exact actual include hashes are in `compile-receipt.json` and `freeze.json` when refreshed. Vendor OpenFOAM template-destructor warnings are retained; they are not reported as a warning-free build.
