## P1: An unordered velocity comparison reuses stale finite wall fluxes for a changed terminal input

Location: `applications/CHMT/gpu/GasWallMath.H:54–61`, especially line 58.

`makeInterfacePrimitive<true>` now computes a terminal nonfinite velocity instead of rejecting it. The next comparison uses `!(mag(preparedVelocity - closure.trace.velocity) > tolerance)`. A NaN difference makes the inner comparison false and therefore selects reuse. Thus changing an originally finite wall velocity, normal, or normal speed to a nonfinite value can retain the old layer's finite traction and conductive heat, while the separately constructed trace uses the new input. This publishes a hybrid of two calculations as a completed current result.

One isolated probe compiles the real frozen `GasWallMath.H` and reuses the existing packet fixture. All arrays, material coefficients, and matching references remain available; only the stated scalar/vector component changes. Results:

- Unchanged input: prepared and fresh results match.
- Finite changed wall velocity (`velocity.y = 3`): prepared and fresh results match, demonstrating the actual recompute route works.
- Changed `velocity.y = NaN`, `velocity.y = +Inf`, `normal.y = NaN`, or `normalSpeed = NaN`: both calls return true, but prepared and fresh layer fields differ.
- In all four terminal mutations, reused traction Y is the original finite `0x1.007041ebe238fp-4`; the actual fresh result is NaN. Reused conductive heat is `-0x1.2e3f48749602cp+13`, while actual fresh heat is `-0x1.2e3c021329a46p+13`.

Evidence: `independent-review-probes/reuse-probe.py`, `reuse-probe.cpp`, `command.txt`, `build.log`, `run.log`. The probe compiles once with g++ C++17/O1, `-ffp-contract=off`, and warnings-as-errors; compile and execution exit 0. Its output explicitly records the mismatches rather than treating them as a passing acceptance assertion.

Required correction: make reuse discriminate matching terminal components from mismatched finite/nonfinite components, and choose the existing real fresh-closure path when the consumed velocity is different. Preserve the original ordinary finite comparison/reuse behavior and matching terminal values. Do not add a numerical refusal, status whitelist, substitute values, or unconditional extra wall solve. Add a focused regression comparing the changed terminal prepared path against a fresh actual closure; retain unchanged/prepared-only/no-workspace compatibility and genuine missing-new-workspace behavior. This is a direct B5 publication defect and does not require B6/B7 scheduler redesign.
