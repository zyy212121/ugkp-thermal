**Request changes on two narrowly scoped native CUDA-free tails.** The successful-path lifecycle, precision and cost evidence is valid for the frozen B6 candidate, but actual free-error handling is not closed. Neither finding calls for a numerical/metadata gate, physical-state snapshot, new admission test, README change, or broader B7 work.

## Findings

### B6-R1 — P2: failed free of a rejected wall candidate loses its only owner

Locations: `applications/gasUGKP/private_backend/BoundaryLayerAdapter.cuh:91,113,124–126`, together with `BoundaryLayerStorage.cuh:11–32` and `SharedGasStorage.cuh:24–35`.

`releaseSharedGasPointer` now correctly retains a pointer when `cudaFree` fails, and `releaseBoundaryLayerStorage` aggregates that result. However, the candidate-discard callers ignore the result. `BoundaryLayerAllocation candidate` is stack-only and has no owning destructor or resident rejected-owner transfer. If preparation fails and any candidate free also fails, the function returns with that allocation reachable only through the departing local candidate. `releaseState` cannot later reclaim it. The analogous cleanup after failure while releasing the old wall has the same lost-candidate tail.

This was reproduced without invalid metadata or OOB access using the actual ABI, allocation/release and publication bodies, with one staging H2D failure and one failed free:

- `candidate preparation rc=1 outstanding=1 poisoned=0 error=free shared gas storage`
- `after resident teardown outstanding=1`

The probe's own accounting pointer was used only afterward to release host fixture memory; production has no such pointer. This is a concrete ownership failure, not merely a lack of exhaustive secondary-fault injection. The antecedent unchecked-free behavior also existed in the base; B6's explicitly required free-error/retained-owner tail is incomplete rather than this being a claimed new successful-path regression.

Required result: preserve every failed candidate-free pointer in live resident-owned teardown storage, report the actual error, and use the existing actual-device-error lifecycle as appropriate. Do not add a metadata refusal or general numerical gate. Check precommit discard and old-owner-release failure followed by candidate discard. Evidence: `independent-probes/wall-candidate-secondary-free.cpp`, `.build.log`, `.run.log`.

### B6-R2 — P2: snapshot free failure is swallowed before successful wall publication

Locations: `applications/gasUGKP/private_backend/BoundaryLayerAdapter.cuh:16,121`; `SharedGasTrialPolicy.cuh:75–81,232–236`; changed primitive `SharedGasStorage.cuh:24–35`.

The actual snapshot release functions remain `void` and discard the newly returned release errors. Both wall replacement and zero-wall disable call this tail and continue. A single failed free of `gasTrial.trial.cells` therefore still permits the ABI to return success and publish a new wall configuration; the old failed allocation remains in the snapshot with its size/valid metadata reset. This is not just a teardown-only failure.

A backed probe using the actual production snapshot release bodies reproduced:

- `wall config after trial-free fault rc=0 outstanding=30 baseline=29 poisoned=0 retained=1 error=free shared gas storage`
- Subsequent normal teardown succeeds, so this particular one-shot case is a swallowed actual error rather than the unreachable-owner leak of R1.

Required result: propagate the actual snapshot-release failure to the configuration result while retaining failed ownership and invalidating only snapshots as required. Reconcile the directly affected release/ensure callers so retained pointers cannot be overwritten after another failed release. No extra validation of values, counts or identities is needed. This is an existing void-caller tail exposed by the now-fallible helper, not a request to reopen unrelated physics. Evidence: `independent-probes/wall-trial-primary-free.cpp`, `.build.log`, `.run.log`.

- CHMT candidate ownership exchanges rebind Buffer fault pointers to surviving owners; the stable `deviceView()` address is preserved. Actual view-copy plus rollback-copy failure retains potentially exposed candidate allocations in `rejected_`. Optional first SST/species failures restore old owners. This accepts the indexed tested transaction paths, not every possible asynchronous failure; the disclosed generic Buffer pointer-clearing free-error semantics remain unchanged.
- Native model configuration preserves all 17 dynamic species pointers, including chemistryAudit; only actual supplied model tables and the species view are replaced. Chemistry disable/enable retains already allocated dynamic/audit storage. Explicit species/boundary imports replace only their own arrays and invalidate snapshots without unnecessary graph recapture.
- Wall configuration remains supplied wall-record import. Already-owned 13-array SST audit storage survives replacement, audit disable, and zero-wall disable. Selected-model/workspace absence and actual alloc/copy/query errors remain real failures; removed species/count/index/nonfinite admission tests have not been replaced by new numeric gates.
- Captured gas kernels, including the RK save kernel, receive `deviceState` indirectly. Capture nevertheless embeds host dispatch/branch/grid choices. Configuration invalidates the existing graph dt key; the next applicable legacy advance uses existing destroy/capture/instantiate. Pointer-only imports preserve capture reuse. The indexed graph probe exercises the real common host protocol and eight actual lifecycle error classes, not GPU graph execution. Node-query/time-parameter faults are unchanged and are not individually newly injected.
- Repeated shared SST configuration preserves k/omega, conservative, initial and nut inventory. Scalar publication excludes the two trailing device-produced Jayatilleke constants. Retained host kappa/E are only last-successful published configuration metadata. `gasPrClamped` and `turbulentPrandtl` assignments were independently checked: defaults, Create, host scrub; no runtime device update exists. The actual original constant formulas read device Pr/Prt. The common initializer's default path retains original FP64 formulas, clamps and operation order; the new false parameter skips inventory initialization only.
- No README modifications, added numerical/precision/version/count refusal, permanent full-state cache, new remap/padding or normal full-state D2H/D2D operation were found in the patch. The two new tests are present in the freeze/patch; the new native mirrored test is registered in `managed_mirrors.json`. The CHMT-only test is not an omitted native managed mirror.

## Remaining scope and closure

R1 and R2 should be closed with the smallest native free-failure tests and directly affected lifecycle/compiler checks. Reuse unrelated B1–B5 and unaffected B6 evidence; refresh the freeze/receipts for changed source. After correction, a focused rereview can approve B6's lifecycle scope.

The following remain explicitly open for B7/global work and are not protected by a prior per-batch approval: upstream `GasModelIO.H::thermoView<Ns>()` size veto; current-stage wall production and dependent face refresh; prepared stage/time/dt/count checks; HostState terminal material sampling; status/numerical retry/commit closure; external topology/shape checks. Actual CUDA copy/sync/IO failures must stay observable when those numeric/status vetoes are removed.

No GPU runtime/asynchronous lifetime stress, OpenFOAM integration/performance, paired-mirror repository verification, whole-PR14 readiness or main merge is approved here.
