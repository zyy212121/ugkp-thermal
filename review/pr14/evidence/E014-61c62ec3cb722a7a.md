## FilmIntegralFields

InitialConditions.H now consumes exactly the actual face prefix f<n through givenM.at(f), givenH.at(f), and givenSpecies[s].at(f). Extra unused entries are accepted. Missing consumed entries remain actual source-access failures. There is no zero padding, new size certificate, numerical preflight, or change to the arithmetic for previously supported inputs. Film initializer selection and exact FilmSine formula restrictions remain unchanged.

## Thermal boundary pairing

ThermalBoundary.H no longer refuses Inlet zeroGradient T or Outlet fixedValue T solely based on the Inlet/Outlet label. Recognized fixedValue/zeroGradient temperature operators still map to the existing enum; unknown operators and absent topology-specific implementations remain errors. The separate strict material validateThermalBoundaries positive-temperature refinement remains unchanged.

Actual dataflow reviewed:

- MeshIO::importGasFields records the thermal operator, then calls OpenFOAM rho/T/U boundary correction before importing the physical boundary primitive.
- SharedGasDeviceStorage.cuh::uploadGeometry copies that primitive's temperature and sets fixT from the thermalBoundary enum independently of inlet/outlet. It preserves the original inlet fixed-rho/velocity and inlet/outlet fixed-pressure flags.
- updateLegacyGasBoundaryMirrorKernel copies owner temperature only when the actual TFix flag is zero.
- makeGasPrimDevice keeps the existing native EOS precedence. For inlet fixed rho+p with T unfixed, it computes T=p/(rho*R); for fixed p+T with density unfixed (including outlet fixedValue T), the existing mixture density expression computes rho. This change does not invent a new boundary formula or promise that the inlet EOS-derived temperature always equals the owner temperature.

## Additional native-main compiler warning classification

The resident worker subsequently compiled the real gasUGKP main translation unit with OF10/CUDA configuration successfully. Its log (`../../resident-followup/gasUGKP-compile.log`) reports `SharedGasModelInput.H:63: rho may be used uninitialized`, in addition to vendor-header warnings. Our combined O0 object compile did not issue it; this is not claimed to be a warning-free whole-application build.

Source classification: the public density producer selects Impl<false>. Both Success and NonFiniteInput assign the actual density result. The only no-write returns are absent massFractions or species storage; pointState sends both through the existing FatalError stream. In OF10, errorManip.H's stream insertion invokes a void member-function pointer and syntactically returns Ostream&, while error.H declares error::exit without a noreturn attribute. error.C's real implementation throws, calls ::exit, or invokes Pstream::exit/MPI_Abort. This prevents the compiler from proving that the fatal stream cannot fall through, even though there is no actual successful no-write producer route. No artificial rho=0 initialization, new rejection, or fabricated output was added to silence the warning. Classification is source-based and independently confirmed by the pass2 reviewer at 15:52 UTC; no runtime probe was run.
