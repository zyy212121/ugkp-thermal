## Root cause and native fix

The old generator followed only `allocate(s->field,...)`, then an installation temporary with `allocate(alias,...)`. Current thermal constructors instead bind real storage by `Scalar*& alias = s->field` and invoke local `acquire`, `pending`, `markPending`, `clearPending` and `initialise` helpers. The old parser therefore reported FSH `pColdFrozenArea: expected one, got 0` despite the actual allocation being present, and it omitted pending-bit initialization expressions.

The fix follows the actual typed reference and copies those helpers and their required real state/constant declarations into the generated probe. It preserves actual allocation count, initialization byte count and labels. It retains direct allocation and historical temporary-installation support. Missing/duplicate actual allocation, wrong typed owner, missing actual initialization and missing helper state are offline development errors, not new solver runtime gates.

The host cudaMemset stub now uses a separate allocated-byte map, so the production `void*` initialization helper retains the exact full-byte assertion without relying on a fictitious typed sizeof(void). Count tracking remains intact for copy/upload/download. The generated CPU probe also invokes the actual acquire/initialize operations a second time on seeded resident cold owners, checking that already initialized owners are neither allocated again nor cleared. This executes production helper bodies, not substitute lifecycle logic.

No production formula, physical type, data traversal, allocation, transfer, synchronization, GPU kernel, restart schema or registry changed. The two generated registry strings remain byte-for-byte fixed-base output. CHT cold 8/64-node enthalpy profiles and their actual compact/host/current-wire float copies are preserved; FSH profiles remain double.
