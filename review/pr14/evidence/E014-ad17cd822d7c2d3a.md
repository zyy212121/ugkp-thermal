## R1: unique rejected-candidate ownership

All four relevant candidate-discard tails now use `discardBoundaryLayerCandidate`: early table/allocation preparation failure, later input/exchange copy failure, snapshot-release failure, and old-wall-release failure. Release still attempts all fields; successfully freed pointers become null. Only actual failed-free pointers survive in the candidate. Those remaining pointers transfer to the resident's embedded `gasTrial.rejectedWall`, and the local candidate is cleared.

The existing actual-error poison prevents another public configuration from overwriting the rejected owner. There is no successful-path condition that can populate rejectedWall; normal configuration reaches the helper with it empty. Accepted wall, retained SST audit, trial snapshots, and rejected candidate remain separate owners. In the old-wall-free failure path the retained audit is restored to the resident and removed from the candidate before candidate discard. Thus old and candidate failures do not alias audit ownership.

The exact `DeviceState&` release overload explicitly releases resident fields and the rejected owner, even if resident release fails. The actual native `releaseState(*s)` call resolves to this overload. A failed release of rejectedWall retains its pointers for a further internal teardown attempt. The new tests cover first/repeated preparation failures, both early/late copy positions, old-wall + candidate failure, snapshot + candidate failure, repeated teardown failure, and final successful release. The v1 stack-only lost-owner path is closed.

## R2 and directly affected replacement tails

Snapshot release now aggregates all seven channels in each of the two snapshot levels; neither level is skipped after a failure. Failed pointers stay resident-owned, snapshots become invalid, and reuse-size metadata cannot certify partially freed storage. Wall replacement and zero-wall disable check that release result before changing/publishing the physical wall. Replacement's already-prepared candidate follows R1's owner-safe cleanup. Snapshot-only free failure therefore returns an actual error while the unchanged wall remains retryable; it does not unnecessarily poison a valid physical owner.

`ensureSnapshot` returns on failed old release before making any replacement allocation. Allocation-failure cleanup retains failed pointers in the live snapshot; the following attempt again releases before allocating. Wall-record resizing returns on failed free before allocation or D2D copy and retains its old byte extent. The tests check zero replacement allocation/copy in these failure paths and retry behavior. The v1 successful wall publication after a failed snapshot free is closed.

The adjacent budget cleanup likewise aggregates its three pointer releases and only clears the audit view once all releases succeed. Its failed configuration cleanup marks the existing actual-error poison when a free fails, so a later configuration cannot overwrite retained budget pointers after the host ledger has closed. The actual enabled-budget allocation + cleanup-free failure is tested and instantiated in the small CUDA compile; this is not an uninstantiated capability-false test.

No new value/count/identity/precision preflight, numerical rollback condition, physical snapshot or dynamically allocated rejected-owner container was added. The new failure returns depend on actual CUDA release errors. Successful physical formulas, field import/order, graph decisions and normal publication calls are untouched relative to v1.

## Cost verdict

The v1/v2 cost comparison uses actual wall ABI and release bodies, including a v1 source overlay. First/repeated/disabled normal wall paths have identical CUDA calls, zeroing and transfer bytes, partial view counts, and host-heap allocation counts. Host allocations remain 6 / 6 / 0. The repaired cleanup traverses a fixed owner manifest; there is no normal O(cell/face count) added snapshot, new CUDA allocation or additional full-state publication call.

The fixed rejected-owner metadata is **376 bytes**, not zero cost. The fixture DeviceState size rises 2376 → 2752. Source tracing confirms the actual native whole-state publication implications:

- one deviceState allocation grows by 376 bytes;
- successful Create performs its two existing full-state copies, so total H2D increases by 752 bytes without another copy call;
- each explicit UploadBoundarySources call takes one existing empty/nonempty full-state copy alternative, adding 376 bytes;
- the current wrapper invokes boundary-source upload from construction; native Advance/AdvanceGasOnly has no syncDeviceState call and gains no per-step full-state publication;
- model/wall/SST partial publication excludes the new rejected owner metadata.

This bounded, disclosed metadata cost is consistent with the fixed resident-owned error-tail repair. No zero-total-overhead claim is accepted. The v1 same-SST 6 H2D / 248 bytes / 0 kernel / 0 sync, changed-kappa/E one-thread update, first-success FP64/transfer parity and CHMT resident costs remain reusable because their code and relevant publication sizes are unchanged.
