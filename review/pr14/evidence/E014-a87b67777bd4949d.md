# Tool precision/control classification

Scope: the 16 Python sources under repository `tools/`, with `managed_mirrors.json` excluded from mutation. This is a tooling inspection, not either of the two pending independent global audits. `tool-token-scan.json` records file hashes and all 63 matched float lines.

## Actual floating types

1. `analyze_heavy_laval_l2.py`, the four `plot_heavy_laval*.py` files, `postprocessing/bartz.py`, and Python conversions/annotations in `run_heavy_laval_l2_benchmark.py`/`benchmark_operator_unification.py`: Python `float` is binary64 in this CPython environment. These are result analysis or postprocessing values, not an active C++ FP32 solver route.
2. `benchmark_operator_unification.py` pointer-declaration regex accepts `float`. It reads actual production DeviceState declarations, including the two established CHT cold enthalpy profiles and their compact copies. Removing that token would omit real owners from the synthesized benchmark state. Its generated `float ms` is required by `cudaEventElapsedTime(float*,...)`; it is timing output, not physical state.
3. `particle_field_contract.py` defines host `float4` solely to execute the actual vectorized copy in `GpuCellLocalThermalFields.cuh`. The real production branch is instantiated only for a packed float scalar profile. The CHT 8/64-node specific-enthalpy profiles, compact copies, host arrays and current wire bytes retain float exactly. The FSH counterparts remain double. No precision choice was added.
4. `common/thermal_particle_restart_current.py` chooses `<f4` only for the two established CHT enthalpy profiles; current FSH bytes use `<f8`. `applications/FSH/tools/fsh_particle_restart_schema6.py` and `GpuThermalParticleRestartCodec.H` contain historic `<f4`/`float` decoding for old schemas. They are read-only historical-format compatibility, not current physical computation precision. They are outside this worker's mutation scope and were left unchanged.
5. Integer widths, CUDA warp size 32, block counts, identifiers, and the string `roundtrip` in lifecycle assertions are not physical FP32 state or mixed-precision rounding-record plumbing.

## Removed/retained controls

- The current 16 tools have zero token matches for active32, UGKWP_GPU_REAL_BITS, gpuRealBits, precisionMode, mixed-precision or rounding-record controls. Fixed commit 63e92e4 removed obsolete precision matrix/CLI-bit plumbing from benchmark_operator_unification, low_level_regression, operator_policy_contract_test, particle_field_contract and validate_shared_operators. Current wrapper command construction supplies root/output/application plus any actual operational mode, never a deleted bits argument.
- `CellLocalThermalExtraFields<false,false>` for FSH and `<true,true>` for CHT match the actual two-boolean template. The scalar is inferred from each actual field. Its packed float copy is the allowed CHT profile-copy path.
- `run_prebuilt_low_level.py` treats source/binary hashes as offline provenance, not execution admission. Missing/outside-bundle executable checks and post-run expected_stdout checks remain actual I/O/safety/correctness checks. `compare_cuda_artifacts.py --require-unchanged` is explicit offline development comparison, not a solver runtime veto.
- `operator_policy_contract_test.py` remains an explicit compiler smoke with actual used-type errors; standard normal builds do not invoke the optional policy inventory checks. `particle_field_contract.py` remains an offline generator/check/probe. Its declaration/allocation/release/transfer checks were repaired, not skipped.
- `GpuParticleThermalCarry.H` / `pThermalEnthalpyResidual` are double physical specific-enthalpy carry plus current-wire extension, with actual producer/consumer updates. They are not inactive mixed32 recording. Dropping them would discard accepted sub-representation enthalpy and change current particle restart state. This worker did not remove them.
- `tools/migrate_scheduling_properties.py` had offline legacy policy checks mismatching the current production scheduling reader. It now removes ignored gpuResearchVariant, canonicalizes an explicitly unknown gpuCsrLevel to the actual L0 success fallback, and preserves negative nonzero auto intervals. The actual zero-divisor error still occurs before any file write. Existing legacy flag translation and idempotency remain covered. This narrow expansion was parent-approved before editing.

## Boundaries

No README, production/common/application files, historical evidence fixtures, shared manifest/index, commits or pushes were changed. No new numerical/precision/version runtime admission gate exists in this patch. All additional checks are within an explicitly requested optional development probe. Full solver linkage, CUDA/GPU correctness, GPU sanitizer and performance evidence are not established by this classification.
