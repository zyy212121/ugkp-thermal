# 用户真实 GPU 应用验收建议（尚未执行）

在有真实 GPU 的原生 OpenFOAM/CHMT/gasUGKP 环境完成整应用编译、链接与运行。当前证据仅覆盖指定主机对象和 sm_80 CUDA 对象可编译，不代表应用可链接、数值正确或性能达标。

1. 正常输入控制：与 B7 基线使用完全相同的有效输入、编译器/精度、网格和运行参数。比较全部启动字段、网格几何、已接受状态输出、重启载荷、边界交换记录；确认原有成功路径保持一致。保留实际 GPU 时间、内存、复制次数与墙面求解次数。
2. CHMT 材料实值：LinearCp R=-1、cp0=2、cp1=e0=0、T=300，应按给定表达式得到 e=900、Cv=3。覆盖材料温度恢复、热容割线、实际二阶重构 Darcy 面通量。补充 R=0、最小非零正数、正负无穷、NaN 和 NASA7 分段输入，记录实际算术结果，不将非有限结果替换为预设零。未配置且质量为零的其他物种须保留原成功路径；保留原浮点异常设置检查。
3. 原生前端物种通量：通过 OpenFOAM 实际可读取的数字字段/二进制字段提供有限值及非有限 speciesFlux。确认 prepare→configureResident→原生墙面生产者→已接受交换的数据贯通、物种顺序和面索引不变。缺失物种条目或补丁仍应报告缺少真实输入。
4. 启动几何：完整有向拓扑中反向单元使用真实带符号体积/质心。检查 importMesh 和 validateRuntimeState 两处；检查零长度表面边、退化法向以及给定负厚度且实际偏移气体顶点匹配的界面。禁止为测试故意构造越界访问；无法找到真实顶点配对时保留缺少映射错误。
5. Empty 挤出映射：有实际存储的 NaN 坐标不会破坏有序容器比较器的严格弱序；正常有限坐标、无穷和正负零的既有次序不变。不要把确定排序误解为存在真实配对，仍核对实际 mate/拓扑结果。
6. 启动和输出：覆盖数值异常但有真实公式的气体密度/温度/组成、固体能量、膜积分量、给定壁温，以及完成状态的气体/材料输出。确认 conservativeGas 的失败哨兵没有代替原始物理输入参与最终算术。
7. gasUGKP 原生前端：给定异常 p/T/Y 时密度和内能由既有公共表达式产生；species 下载在 rho=0 或非有限值时真实执行 value/rho 和场写入。公共数字解析允许 strtod 的真实非有限结果，但格式错误仍失败。

已知未闭合项：CHMT 的公共边界层剖面输入仍只有 strict adapter 的 molarMass，缺少原始 R 通道；本次材料修复不能宣称解决该路径上的非正/不可表示 R。该项需单独审查与实现设计，不能通过无条件 Ru/R 破坏原本成功的零质量、未配置物种路径。
