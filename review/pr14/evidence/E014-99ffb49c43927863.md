## Findings

### B2-R1 — P1: new nonfinite transport entry changes an original successful result

`computeRiemannGasFaceFluxDevice.cuh:937–939` adds `|| (!nativeRefinement && !transportFinite)` to the original positive-coefficient branch. The original branch returned normally when both comparisons were false. With the same backed mixture fixture used by the new test (`gasMu=NaN`, direct conductivity zero, IncludeTurbulence=false, Ux 0/2), immutable base and candidate both return success=1 and status=0, but:

- Base: five finite bulk values, including momentum X `0x1.95fbc860ca87bp+17` and energy `-0x1.3721a1fa56d75p+29`.
- Candidate: mass remains `0x1p+0`; momentum XYZ and energy become NaN.

That is an original-success regression, not a formerly refused tail. The candidate's `nonfinite_coefficients` assertion codifies the regression. Preserve the original successful selection/bytes and correct that expectation. Evidence: `independent-gap/old-success-transport.cpp`, two compiler logs, `old-success-transport-receipt.json`. Both probes ran at g++ -O2 -ffp-contract=off; the archived original face header was byte-verified against base HEAD before use.

### B2-R2 — P1: legacy numeric paths still trap before publication

`computeGasInternalFaceFluxKernel.cuh:63–67` and `computeGasFluxPositivityScaleKernel.cuh:60–62` retain `asm("trap;")` when recording a numeric status is impossible. Plain `GasStateView` has speciesCount=0 and no species status array, so these conditions always trap on the numeric failure even with all consumed backing present.

The independent single-binary probe exercises two legitimate allocated cases: nonfinite periodic bulk, and NaN consumed V with positive outgoing mass. Both terminate with SIGABRT (-6) under the real CPU-body shim before the terminal writes. Expected publication follows the unchanged average formulas and positivity comparison/clamp route. Numeric-only continuation must not depend on an optional status channel. Preserve actual missing-storage errors.

Evidence: `independent-gap/legacy-gaps.cpp`, `build.log`, `receipt.json`. No out-of-bounds addressing, mock output, or production edit was used.

### B2-R3 — P1: partial-property count label still substitutes NaN for real enthalpy

`SpeciesDiffusion.H:50–65` now treats B1 `evaluateSpecies`'s availability flag as real evaluation. However `MixtureThermo.H:72–83` retains a property-level metadata shortcut: when two LinearCp coefficients are declared, Cp metadata is valid, but h is assigned `invalidValue` instead of executing the backed third-coefficient formula. NASA7 has the equivalent five-versus-six-coefficient case at 99–102.

The original six-element backing is unchanged. Only coefficientCount is set to five. Diffusion writes its actual finite species fluxes, sets evaluated=true, and writes enthalpyFlux=NaN; evaluating the supplied formation enthalpies gives exactly 90000. This violates the terminal formula-completion contract. Existing coefficientCount=1 coverage takes a different branch (`!declared`) and therefore does not catch it.

Fix the selected terminal enthalpy/energy consumer and preserve original successful Cp-only/generic material calls and strict metadata selection. A broad change to every bundle/property consumer risks repeating B1's already repaired old-success problem. Evidence: `independent-gap/partial-count-enthalpy.cpp`, `partial-count-build.log`, `partial-count-receipt.json`.
