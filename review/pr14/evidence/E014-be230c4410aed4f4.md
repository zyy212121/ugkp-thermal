## Precision and residual classification

The source scan of all425 C/C++/CUDA production files under applications/common found no additional explicit active physical float store outside the allowed CHT cold1D[8]/cold2D[64] profiles and their actual compact/host/current-wire copies. GpuReal/GpuTime/GpuWallEnergy are fixed double; FSH/Gas native operators select double; CHMT Real is double. This is a source/type-path conclusion for current owners, not proof about arbitrary external OpenFOAM scalar build modes or every possible generic template instantiation.

- CHT profile publish uses float and nextafterf intentionally; read-side caloric accumulation promotes these actual cache values to double. float4 in GpuCellLocalThermalFields copies allowed packed profile bytes and does not calculate another physical float field.
- CUDA event elapsed-time float is the API type, not physical simulation precision.
- Schema7/older readConverted<float> and wire markers describe historical decoding, not current FP32 physics. Current CHT schema9 retains only the two profiles; current FSH schema8 physical payload is double.
- Python float is binary64. The tools report/token classification is consistent with this distinction; tools' old active precision CLI/rounding-route strings were removed earlier. Initial tool freeze matched all4 source entries at comparison time.
- pThermalEnthalpyResidual is **not obsolete mixed-precision bookkeeping**. It is double specific enthalpy carried alongside temperature/profile state; effectiveParticleEnthalpy, paired heat, finite-contact heat, material moments, affine radiation, compaction and restart consume it. Sub-double-ULP heat survives in this component. Removing it would change physical state and conservation. Its8 bytes per actual owner/copy is not automatically wasted storage.
- Stale prose remains in GpuParticleRadiationMath.H referring to particle temperature as a float cache, and GpuPressurePipeline mentioning precision selection. Current declarations are double; these are documentation cleanup candidates, not active precision controls or permission to change README.

Exact float hits are in physical-float-scan.txt. The scan is not an assertion that comments/templates/test names constitute active floats.
