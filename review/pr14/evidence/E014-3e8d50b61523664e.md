## Why terminal wall conversion does not break original inactive-table success

Eager unconditional Ru/R in every default CHMT adapter remains prohibited: originally successful condensed/material states construct inactive R=0 tables with floating traps enabled. Default behavior remains exactly the v1 strict adapter.

The actual completed common wall owners are different:

- ConstantTransportWallImpl calls `detail::trace`; WallModelTypes.H::trace unconditionally computes `Y[j]*Ru/molarMass[j]` for every species. A coerced M=0 is therefore consumed even for Y=0 (0/0).
- ReactingWallLayer.H::makeContext unconditionally performs the same weighted quotient for every species. Its pointState also evaluates each species constant and density algebra.
- GasWallMath's prepared-layer reuse calls the original makeInterfacePrimitive<true>, whose original common SpeciesValues path unconditionally calculated Cv=cp−Ru/M for every species and weighted it. A zero-fraction M=0 table still participates in nonfinite arithmetic.

These original wall paths did not have a successful inactive-R0, FPE-enabled outcome that the terminal conversion could newly break. This is source proof, not new runtime evidence. The direct terminal primitive now uses supplied R, and the common wall profile receives actual native M; their formerly-invalid-R arithmetic changes intentionally.

Native quotient details: representable finite negative R gives signed M=Ru/R; R=±0 gives signed infinity; sufficiently small nonzero R can overflow M to signed infinity; R=±infinity gives signed zero; NaN gives NaN. Subsequent common Ru/M arithmetic consumes these actual representable values. With floating exceptions enabled the actual division/overflow may trap. No synthetic zero metadata is substituted in these terminal wall owners, and no exact original-R representation is claimed after native quotient overflow.
