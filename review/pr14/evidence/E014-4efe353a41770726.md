## Findings

### B3-R1 — Important / P2: divergence rejects unconsumed face storage before legitimate skips

Location: `common/operators/computeSstFaceFluxKernel.cuh:1079–1080`.

The new unconditional `!gasSpecies.flux || !gasSpecies.faceStatus` check runs before the cell incidence loop and its existing invalid-face and ownership skips. These arrays are not consumed when the loop is empty or when every face is skipped. The immutable base completes those calls successfully with absent face arrays; the frozen implementation instead records `InvalidStorage` and returns before the actual conservative update. The always-consumed species inventory is a different case and still needs its real backing.

A minimal, independent actual-kernel probe covers strict/direct routes, absent flux / face status / both, and five original-success shapes: count 0, negative zero-trip count, all invalid face IDs skipped, a face belonging to another cell skipped, and empty moving-volume transport. All accesses are within valid backing or skipped before dereference; no out-of-bounds test was run.

Results:

- All 30 base cases return status 0; all 30 frozen cases return status 1 (`InvalidStorage`).
- The six moving cases make the error observable beyond status: for old/new volume 1/2, base density, energy and both species halve. Frozen density, energy and species remain unchanged.
- This affects both native strict and direct terminal calls. It contradicts the brief's preserved zero-trip/ownership/invalid-face success paths and the report's claim that these are only consumed-backing checks.

Evidence: `independent-probes/check_skipped_storage.py`, `skipped-storage.cpp`, `skipped-storage-{base,frozen}.log`, and `skipped-storage-receipt.json`. Both actual C++ probe builds and runs exit 0. Base stdout SHA256: `13afbf08629f3ada373a49776cd38032410aeba55ab6f0a9b25389496463f988`; frozen stdout SHA256: `f44662c4549876de18a91db2ffc5bd0336bd05b4d685bf27d1d8fdf28f30b35f`.

Required correction: retain actual missing-consumed-storage errors, but make the face-array check conditional on reaching its existing consuming point after all legitimate face/index/ownership skips. Do not add a face prescan, count-based admission rule, status whitelist, replacement values or an extra traversal. Add a focused old-success regression covering unused face backing, including the moving-volume final fields, while retaining the existing missing-consumed-storage controls.

### B3-R2 — Important / P2: changed launch signatures break unchanged direct-consumer tests

Changed call sites: `common/GpuGasAdvance.cuh:657,661`. Affected test stubs: `tests/gas_transport/test_gas_advance_view.py:202,242,244`.

The convective launch now passes a third route argument and the SST stability launch passes five arguments. The unchanged chemistry/preparation fixtures still declare two-argument convective and three-argument SST stubs. Consequently these existing tests fail C++ compilation before their successful order/no-dead-predictor assertions run:

- `test_chemistry_composition_preserves_order_without_post_half_quality_gate`
- `test_shared_preparation_does_not_compute_dead_sst_admission_predictor`

Independent targeted pytest result: **2 failed**, with `no matching function` diagnostics for the new arities. The exact unchanged test functions, using headers verified against the immutable base, both pass. This is a B3 direct-consumer regression, not an old numerical-refusal expectation to delete or weaken.

Evidence: `independent-probes/consumer-tests.log`, generated sources in `consumer-tests/`, `check_baseline_consumers.py`, `baseline-consumer-receipt.json`, and `baseline-consumers.log`.

Required correction: update only the affected stubs to match the real route parameters and keep all existing successful trace/order assertions. Where a stub observes an executing strict route, check its actual forwarded mode rather than silently ignoring the new argument. Rerun these two affected tests; a whole-suite rerun is unnecessary for this finding.
