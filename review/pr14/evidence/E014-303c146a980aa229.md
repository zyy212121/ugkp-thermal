## Findings

### A1 / P1: a completed numerical wall exchange is classified as unavailable, so the native interval still stops

Affected classification: `common/operators/computeRiemannGasFaceFluxDevice.cuh:76–79`.

The condition combines missing/not-ready exchange with `nativeRefinement && (boundaryKind != 2 || !finiteDevice(exchange.mass))`, then records `InvalidStorage` for both. The numerical branch is not missing backing or unavailable output. The real wall producer can finish all fields, mark both readiness facts true, and publish a non-finite mass resulting from supplied arithmetic.

The downstream change makes the distinction consequential: `SharedGasTrialPolicy.cuh:204–220,281–298` treats any `InvalidStorage` as true unavailability, clears terminal eligibility, and has no retryable category for this code. `common/GpuGasAdvance.cuh:781–785` consequently rolls back and returns failure instead of executing the existing public operator over the actual remaining interval.

A single focused native host fixture compiled and ran using the production wall model, exchange publisher, face operation, real native policy, requested-interval owner, and public trial. Two individually finite `DBL_MAX` supplied species fluxes produce an actual overflowing total. The retained output is:

- Producer: `completed=1 ready=1 massReady=1 mass=-inf status=6 faceStatus=0`
- Strict face/policy: `return=0 faceStatus=1 validate=1 retryable=0 terminal=0`
- Same requested interval: native owner returns `1`; identical direct public trial returns `0` and actually computes `direct_energy=-nan`

Thus this is not a diagnostic-only test, injected status, stale prefilled exchange, or unsupported model. The ready wall was produced by the actual constant-transport model. The direct path supplies a concrete available terminal continuation.

Required correction: distinguish missing/unready backing from strict numerical/metadata diagnosis at this existing face consumer. Keep the true `InvalidStorage` case; ensure a ready numerical exchange can reach actual terminal work. Do not hide the code globally, fabricate fields, add a validation pass, or alter successful strict arithmetic/partitioning. Add the focused regression to the maintained tests, with a genuine missing-exchange control.

### A2 / P2: the wall producer retains a now-unused face-owner backing gate

Affected guard: `common/gasTransport/GasBoundaryLayerModelState.H:63–69`, specifically `!state.faceOwner` at line 66.

B7 removes the only `state.faceOwner` read from `evaluateGasBoundaryLayerSlot` (the former face/owner index check), but leaves this pointer requirement. The actual local model consumes its supplied face mapping, matching cells/weights, bulk arrays, and wall geometry; it does not read `faceOwner`. A null owner mapping therefore refuses this calculation before a consumer uses that mapping.

The same focused executable verifies `UNUSED_OWNER completed=0 status=1` when only that unused local pointer is removed. The pointer is restored before any common face computation. The code inspection establishes that the gate, rather than an actual read, causes this result.

Required correction: remove the stale local pointer veto. Keep the eventual common face consumer's need for actual owner backing distinct; this finding does not authorize using an absent owner mapping there or inventing an owner.
