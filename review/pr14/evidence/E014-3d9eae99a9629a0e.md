## Interface choice: preserve successful retries and fallback seeds

Completion is an optional trailing template flag on species/mixture/caloric evaluation, preserving existing explicit template spellings. Public non-refinement producers complete numeric-failure outputs while retaining their existing status. Strict trials remain transactional.

MixtureEnergyEvaluator::operator() explicitly disables completion even for Refinement=false. invertCaloricEnergy uses the original evaluator/status selection for endpoints, brackets, Newton/midpoint updates, saved fallback, zero/one iteration effort, and tolerance stops. Nothing is published into the caller's T for strict trial failures. A false-path failure with an already available saved result still returns the original successful saved fallback, with no added evaluator call.

Only an original terminal failure without any available candidate completes the actual failed trial. If an arbitrary evaluator returned Success and its actual values were nonfinite, that existing trial was evaluated and its T is published with the original numeric status. An arbitrary callback's own error is not ignored or retried, and its unwritten outputs do not become results. The known mixture evaluator alone has a separate completion method, which computes its real numeric energy/capacity bundle and distinguishes missing backing from numeric failure. Nonfinite-target terminal recovery actually evaluates the selected existing finite seed or interval midpoint once, instead of claiming an unevaluated cache or proposal.

recoverGasPrimitiveCell(...,false) completes eight mixture primitive fields or five moving-legacy fields from the real inventories, even when an old status is already set. It retains the old status/first numeric failure and does not modify conserved mixture inventories. Its true retry prefix stays transactional. Static legacy finiteOr/clamps, fmax, and conditional conserved repairs are unchanged. Final consumer status cleanup is intentionally B7's work.

## Local cost / gate / precision self-review

- No heap allocation, full-state snapshot/cache, new inventory copy, normal-path species loop, or new synchronization was introduced. Original species summation order and FP64 expression grouping are kept.
- Recovery reuses its original partial-density array and original cp/species loop. The raw bundle replaces speciesCp's existing bundle evaluation; it does not add another loop or full bundle allocation beyond the existing local POD. A carried failure integer/bool and inline completion dispatch are the new local bookkeeping.
- Successful density/caloric paths publish once as before; completion stores occur only on their original numerical refusal path. The successful inversion path has no extra evaluation. A known-mixture terminal failure can add one real full-mixture evaluation at the actual failed trial; nonfinite-target failure adds one chosen-candidate evaluation. An unknown failing generic evaluator is not called a second time. No fake integrated time or finite default state is published.
- No runtime physical/numerical refusal, rollback, cutoff, certificate, or admission condition was added. All original strict/refinement choices remain available to retries. One actual missing species pointer is now reported as InvalidModel before EOS, allowed by the task's true missing-input exception. The existing validMetadata addressability/model/available-coefficient rules are unchanged, and do not manufacture missing coefficients.
- New production calculations use Real/Energy/GPU_OPERATOR_REAL; no float path, scalar downcast, changed clamp/fallback, or modified successful formula was introduced. Host bit equality is documented; it does not establish device numerical parity.
